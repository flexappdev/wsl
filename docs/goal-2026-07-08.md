## WSL-V3.0 — Kill seed mode, wire live data layer

**Branch**: `feature/v3-live-data` · **Session**: Integration · **POMs**: 3

**Context**
Next.js App Router on Vercel, MongoDB (`MONGO_URI` currently unset — app falls back to seed and prints `data · seed (no MONGO_URI)` in footer). Tickers, counters, and leaderboards all run from hardcoded seed values (BTC 71,204, EUR/USD 1.0834). Sources listed on `/about`: UN DESA, OWID, World Bank, IMF, IEA, NOAA, OpenSky.

**Task**
Stand up the real data layer — Mongo connection, upstream fetch jobs with caching, and a single `/api/stats` endpoint that the dashboard reads instead of seed constants.

**Requirements**
1. **Mongo connection** — `/lib/db.ts` cached connection singleton, reads `MONGO_URI`, throws a clear error at build if unset in production.
2. **Ingest jobs** (Vercel cron) — `/app/api/cron/ingest/route.ts` runs every 15 min:
   - FX + commodities + BTC via free tier (`exchangerate.host` + `coingecko`) → `tickers` collection with `fetchedAt`.
   - CO₂ ppm from NOAA Mauna Loa CSV → `climate` collection.
   - Flights-in-air count from OpenSky → `flights` collection.
   - Each fetch: 3 retries, exponential backoff. On failure: keep last-known value, set `stale:true`.
3. **Stats API** — `/app/api/stats/route.ts` returns `{ tickers, population, climate, flights, updatedAt, mode: 'live'|'stale'|'seed' }`. Edge cached 60s.
4. **Client counters** keep the projection model (births/sec, etc.) but rebase from API values, not seed constants.
5. **Footer data badge** reads `mode` from API: `data · live` / `data · stale (last: {time})` / `data · seed`. Remove the `(no MONGO_URI)` leak — never print env internals.
6. **Fix version mismatch** — single `VERSION` constant in `/lib/version.ts` consumed by header badge + footer.

**Outputs**
- `/lib/db.ts`, `/lib/version.ts`
- `/app/api/cron/ingest/route.ts`, `/app/api/stats/route.ts`
- `vercel.json` (cron schedule)
- Modified: header badge, footer badge, ticker + counter components.

**Acceptance (red → green)**
- Red: e2e — footer shows `data · seed`; test asserts `data · live` after ingest → fails initially.
- Green: cron writes real values; `/api/stats` returns `mode: 'live'`; footer prints it.

## WSL-V3.1 — Real live feed + honest news module

**Branch**: `feature/v3-live-feed` · **Session**: Integration · **POMs**: 2–3 · **Depends on**: `feature/v3-live-data`

**Context**
Hero module "Right now in the world" is permanently stuck on `Loading live feed…`. "Latest" section shows seed headlines with fake relative timestamps (`Reuters · 2m ago`) directly under the claim *"nothing here is invented"* — credibility risk. Data layer from V3.0 exists (`/api/stats`, Mongo, cron ingest).

**Task**
Ship a working generated-event feed driven by real rates, and convert Latest into an honest RSS-backed news module.

**Requirements**
1. **Live feed engine** — `/lib/feedEngine.ts` generates events **client-side** from live rates: "~1,000 babies born since you opened this page", "flight count changed +214", "CO₂ +X t in the last minute". Every event tagged `projection` and labelled as such in UI. Fires every 4–8s, max 30 items, newest on top with slide-in.
2. **Kill the dead loading state** — feed renders first 3 events immediately from the current API snapshot; no network-blocked empty state ever.
3. **Latest news** — `/app/api/news/route.ts` pulls 6 items from real RSS feeds (Reuters world, NOAA news, UNWTO) via `rss-parser`, cached 30 min in Mongo `news` collection. Real timestamps only. If feeds unavailable → hide the module entirely. Never show seed headlines with fake ages.
4. **Tag pills** per item (tourism / climate / pop / energy) mapped from feed source.

**Outputs**
- `/lib/feedEngine.ts`, `/app/api/news/route.ts`
- Modified: `RightNowFeed` component, `Latest` section component.

**Acceptance**
- Red: e2e — `/` hero shows `Loading live feed…` after 5s → fails.
- Green: hero renders ≥3 events within 500ms; `/api/news` timestamps match RSS `pubDate` exactly.

## WSL-V3.2 — Country profile pages (SEO surface)

**Branch**: `feature/v3-country-pages` · **Session**: Scaffold · **POMs**: 3

**Context**
Site currently has 9 routes; leaderboards name-drop countries but nothing is clickable to a profile. Featured destination (Morocco) proves the card format. Country pages are the classic stats-site SEO play (Worldometer model).

**Task**
Generate statically-rendered `/country/[slug]` pages for all 195 countries from one countries dataset, each with live-projected population, key indicators, and internal links.

**Requirements**
1. **Dataset** — `/data/countries.ts` — per country: `slug`, `name`, `flag` emoji, `region`, `capital`, `currency`, `languages`, `population` (base + growth rate for projection), `gdpNominal`, `arrivalsPerYear`, `area`. Source: UN DESA + World Bank 2024 figures.
2. **Route** — `/app/country/[slug]/page.tsx` with `generateStaticParams` for all 195. Sections:
   - Hero (flag, name, region, live population counter projected from base + rate).
   - At-a-glance grid (matches the Morocco card fields).
   - Rank badges (population rank, GDP rank, arrivals rank).
   - 3 related-country links (same region).
3. **`generateMetadata`** per page: title `X — population, GDP & tourism live`, description with live figures, OG tags.
4. **Wire every country mention** on the dashboard leaderboards + Destinations page to its profile.
5. **`/app/sitemap.ts`** — include all country URLs.

**Outputs**
- `/data/countries.ts`, `/app/country/[slug]/page.tsx`, `/app/sitemap.ts`
- Modified: leaderboard rows, Destinations cards (link wrapping).

**Acceptance**
- Red: e2e — `/country/morocco` 404s → fails.
- Green: 195 pages return 200; sitemap includes all; leaderboard row clicks route correctly.

## WSL-V3.3 — Share cards + embeddable widgets

**Branch**: `feature/v3-share-embed` · **Session**: Integration · **POMs**: 2–3

**Context**
Next.js on Vercel — `@vercel/og` available for edge-rendered OG images. No share mechanics exist today. Stats sites grow via screenshot/share loops and blog embeds.

**Task**
Add dynamic OG image generation for key stats and country pages, plus a copy-paste iframe widget for the population counter.

**Requirements**
1. **OG images** — `/app/api/og/route.tsx` `@vercel/og` edge function. Params: `?type=population|co2|tourism|country&slug=`. Dark console styling matching site, big number, WSL wordmark, `worldstatslive.org` footer.
2. **Wire `generateMetadata`** on dashboard + country pages to the OG endpoint.
3. **Share button** on each hero stat card: Web Share API with clipboard fallback, shares page URL (OG card does the visual work).
4. **Embed widget** — `/app/embed/population/page.tsx` — minimal live population counter, transparent-capable, no nav/footer. Add "Embed" option in share menu that copies the iframe snippet.
5. **`X-Frame-Options`** — allow embedding only on `/embed/*` routes; deny elsewhere.

**Outputs**
- `/app/api/og/route.tsx`, `/app/embed/population/page.tsx`, `/components/ShareButton.tsx`
- Modified: stat cards, country page metadata, `next.config` headers.

**Acceptance**
- Red: `curl /api/og?type=population` returns 404 → fails.
- Green: returns a valid PNG ≤ 1MB (Edge cap) with WSL branding; iframe embed renders in a plain HTML page.

## WSL-V3.4 — ArtefaiPass hook + Pro surface

**Branch**: `feature/v3-artefaipass` · **Session**: Integration · **POMs**: 3 · **Depends on**: `feature/v3-country-pages`

**Context**
WSL is an Artefai network app. Network model: one Stripe account, Supabase entitlements table, ArtefaiPass £7/mo all-access. Login button exists but is unwired. **Free tier stays fully usable** — Pro sells power features, not the data.

**Task**
Wire Supabase auth + entitlement check, gate three Pro features (country compare, CSV export, threshold alerts), and add the ArtefaiPass upsell surface.

**Requirements**
1. **Auth** — Supabase magic-link login wired to the existing Login button. `/lib/supabase.ts` client + server helpers. Entitlement check: `entitlements` table lookup `(user_id, product='artefaipass', status='active')` — shared network schema, read-only from this app.
2. **Compare mode** — `/app/compare/page.tsx` — pick 2–4 countries, side-by-side indicator table + relative bars. Free users see the page with a **blurred second column** + ArtefaiPass CTA.
3. **CSV export button** on all leaderboards and country pages — Pro only, generates client-side from the dataset.
4. **Upsell component** — `/components/PassGate.tsx` — wraps any Pro feature, shows lock state, "£7/month — every Artefai app" copy, links to network checkout URL (env: `NEXT_PUBLIC_PASS_CHECKOUT_URL`).
5. **Nothing currently free becomes gated.** No paywall on dashboard, country pages, or feeds.

**Outputs**
- `/lib/supabase.ts`, `/app/compare/page.tsx`, `/components/PassGate.tsx`, `/components/ExportCSV.tsx`
- Modified: Login button, leaderboard components, country page.

**Acceptance**
- Red: e2e — Login button click is a no-op → fails.
- Green: magic-link email sent, callback sets session; `/compare` blurs second column for anonymous, shows all columns for Pro entitlement.
